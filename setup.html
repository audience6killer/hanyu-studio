HSK5 Studio · one-time setup

Sync your desk.

The app works entirely on its own. This page connects it to your own Supabase project so the laptop and iPhone share one progress history. It takes about fifteen minutes and stays on free tiers.

← Back to the app

What you need

  • A Supabase account (free) for the progress row and email/password login.
  • A free GitHub account and repository (recommended: the included workflow deploys on every push to main), or Netlify Drop / Cloudflare Pages for a manual deploy.
  • If you deploy manually: the hsk5-studio-site.zip produced by python tools/prepare_deploy.py, or the deploy/ folder.
The public anon key is meant to be embedded in a browser app. Row-level security keeps every user to their own row. Never paste the service_role key into the app.

1. Create the Supabase project

  1. Sign in at supabase.com/dashboard and create a new project. Choose a region near you and save the database password somewhere safe.
  2. Open SQL Editor → New query.
  3. Paste the SQL below and press Run. It creates the progress table, row-level security, and the atomic save function.
Copied 
-- HSK5 Studio / Supabase sync schema
-- Run this once in the Supabase SQL editor for your project.
-- It creates one row per authenticated user and an atomic save function
-- that refuses to overwrite a newer revision.

create table if not exists public.progress (
  user_id uuid primary key references auth.users(id) on delete cascade,
  state jsonb not null,
  rev bigint not null default 1,
  updated_at timestamptz not null default now()
);

alter table public.progress enable row level security;

drop policy if exists "progress_select_own" on public.progress;
create policy "progress_select_own" on public.progress
  for select to authenticated
  using (auth.uid() = user_id);

-- The client never writes the table directly; only the function below does.
revoke all on public.progress from anon, authenticated;
grant select on public.progress to authenticated;

create or replace function public.save_progress(p_state jsonb, p_base_rev bigint)
returns table (rev bigint, state jsonb, conflict boolean)
language plpgsql
security definer
set search_path = public
as $$
declare
  v public.progress%rowtype;
begin
  if auth.uid() is null then
    raise exception 'not authenticated';
  end if;

  select * into v
    from public.progress
   where user_id = auth.uid()
   for update;

  if not found then
    insert into public.progress (user_id, state, rev)
    values (auth.uid(), p_state, 1)
    returning * into v;
    return query select v.rev, v.state, false;
    return;
  end if;

  if v.rev <> coalesce(p_base_rev, 0) then
    return query select v.rev, v.state, true;
    return;
  end if;

  update public.progress
     set state = p_state,
         rev = v.rev + 1,
         updated_at = now()
   where user_id = auth.uid()
   returning * into v;

  return query select v.rev, v.state, false;
end;
$$;

revoke all on function public.save_progress(jsonb, bigint) from public;
grant execute on function public.save_progress(jsonb, bigint) to authenticated;

2. Make sign-in convenient

  1. In Supabase, open Authentication → Providers → Email.
  2. For a personal single-user desk, turn Confirm email off and save. Then the app can sign in immediately. If you leave it on, create the account, click the confirmation link in your inbox, then sign in.
  3. Open Project Settings → API and copy the Project URL and the anon public key. You will paste both into the app, not here.
  4. If you keep email confirmation on, set Authentication → URL Configuration → Site URL to the HTTPS address where you deploy the app, so the confirmation link returns you there.

3. Put the app online

  1. GitHub Pages (optional; requires working GitHub billing): push this folder to a GitHub repository's main branch, then open the repository's Settings → Pages → Build and deployment → Source and choose GitHub Actions. While the GitHub account is billing-locked this workflow cannot run, so use Netlify or Cloudflare below. If billing is fixed, restore the push trigger in .github/workflows/deploy.yml. The URL is https://USER.github.io/REPO/.
  2. If the repository is private on a free plan, GitHub Pages requires a paid plan. Either make the repository public (the app contains no account secrets) or use one of the free Git integrations below; no billing is required for either.
  3. Netlify (free, automatic): at app.netlify.com choose Add new site → Import an existing project → GitHub. The checked-in netlify.toml builds with npm run build and publishes deploy. Set the production branch to main; every push redeploys. Use the *.netlify.app URL.
  4. Cloudflare Pages (free, automatic): in Cloudflare choose Workers & Pages → Create → Pages → Connect to Git. Framework preset None, build command npm run build, output directory deploy, production branch main. Use the *.pages.dev URL.
  5. Manual preview: run python tools/prepare_deploy.py, then drag deploy/ (or hsk5-studio-site.zip) to app.netlify.com/drop or upload it to Cloudflare Pages → Direct Upload.
  6. Open the deployed URL once on the computer that already has your progress. Any later push to main updates the same URL on Pages, Netlify or Cloudflare.
Netlify access control: a new Netlify site can be behind Edge Access / Visitor access, which shows a Netlify login redirect (HTTP 401) instead of the app. For a home-screen study app, open Site configuration → Access & security → Visitor access and make the site public, or log in on the phone. This is separate from the app's Supabase account.
Automatic deploy: the GitHub Pages workflow, Netlify and Cloudflare all inject the current SQL into setup.html and stamp a new service-worker cache version, so an installed iPhone app picks up new assets on its next launch. The GitHub Pages workflow is already manual-only while the GitHub account is billing-locked, so it will not run on pushes.

4. Connect the work computer

  1. In the app: Settings → Cloud sync.
  2. Paste the Project URL and anon key, enter your email and a password of at least six characters, and press Create account. If confirmation is on, confirm by email and then sign in.
  3. The first sync uploads this browser's existing progress. If it asks, choose Upload this device — the cloud row is still empty.
  4. Check that the status reads Synced … and a revision number appears.

5. Add it to the iPhone

  1. Open the same HTTPS URL in Safari.
  2. Tap Share → Add to Home Screen. Open the new icon; it runs full-screen and caches its files for offline study.
  3. In the app: Settings → Cloud sync, sign in with the same email and password, then tap Sync now (or Download from cloud on a fresh phone).
  4. Your vocabulary, cards, lesson stages and attempts appear. Work offline on either device; the next connection merges both sides.

How the merge behaves

Vocabulary and cardsUnion. A card reviewed on both devices keeps the later review; reps and lapses take the larger count.
LessonsStage completion is unioned; completed lessons stay completed.
Daily totalsPer-day maximum, not a sum, so a session is not double-counted.
Exams and essaysUnion by timestamp; nothing is silently dropped.
Plan and settingsThe most recently changed configuration wins. Changing the target date on one device propagates after the next sync.
Current sessionThe later active session wins. Sync pauses while a session is open so the runner is not replaced mid-card.

Troubleshooting

  • “The progress table is missing” — run the SQL above, then press Sync now.
  • “Email not confirmed” — confirm the email, or turn Confirm email off in Supabase Auth settings.
  • Network error — check the Project URL begins with https://, the anon key is the public one, and the phone/computer is online.
  • Sync status says signed out — sign in again; tokens expire but the local progress is untouched.
  • Offline install did not update — close the home-screen app completely and reopen while online; the service worker refreshes its cache.

Backups still matter. The cloud row is one JSON snapshot. Use Settings → Export backup before resetting a device or changing projects. Nothing except this snapshot is sent; the app makes no other network requests.
